# Память ISP: 5 ГиБ

`resize_isp_memory.py` меняет только память существующих ISP с 4096 на 5120 МиБ.
Фиксированный список: 10101, 10201, 10301, 10401, 10501, 10601, 10701, 10801,
10901, 11001, 11101, 11201, 11301, 11401, 11501, 11601.

Запуск от root на Proxmox-ноде, где находятся все 16 ВМ:

```bash
python3 resize_isp_memory.py          # показать план
python3 resize_isp_memory.py --apply  # применить
```

Имена целей должны быть ISP либо заканчиваться на -ISP/_ISP.
Проверка всех целей выполняется до первой записи. При отсутствующей ВМ,
другой ноде, блокировке, ballooning или посторонних отложенных изменениях скрипт
останавливается. Повторный запуск пропускает уже заданные или отложенные 5120 МиБ.
Скрипт не уменьшает память ВМ, у которых сейчас больше 5 ГиБ.

ВМ не удаляются, диски, сети, protection и параметры процессора не меняются.
Скрипт не останавливает и не запускает ВМ. Для работающих гостей увеличение может
остаться отложенным: потребуется полное штатное выключение и последующий запуск
из Proxmox. Перезагрузка только внутри гостя может не применить новое оборудование.

Суммарная память этих 16 ВМ после применения: 80 ГиБ вместо 64 ГиБ. Убедитесь,
что на хосте хватает памяти для дополнительной нагрузки и остальных ВМ.
Настройки до изменения сохраняются в /root/isp-memory-5g/*.json.
Если выполнение прервалось, ранее обработанные ВМ могут уже иметь новую настройку;
устраните причину и повторите команду. Автоматического отката нет.

Проверка: 7 локальных тестов с имитацией Proxmox; на реальной ноде не запускалось.
Увеличение памяти помогает при её нехватке; ускорение работы не гарантируется.
Скрипт миграции ОС не запускается и остаётся отдельным инструментом.
