# ISP на EcoRouter в существующих ВМ Proxmox

Сценарий заменяет загрузочную ОС выбранных ISP на EcoRouter, сохраняя VMID,
старые диски и флаг `protection`. HQ-RTR, BR-RTR и остальные ВМ не меняются.
Гостевые DHCP, IP-адреса, маршруты и NAT не настраиваются. Подключение WAN
сохраняет возможность дальнейшей ручной настройки внутри EcoRouter; поддержку
DHCP-клиента конкретной версии образа этот пакет не подтверждает.
Это отдельный инструмент для существующих стендов; установщик PavelAF для
нового развёртывания в этот пакет не входит.

## Пошаговый запуск через curl

Команды ниже рассчитаны на **16 ISP**: `10101, 10201, …, 11601` с шагом 100.
Каждый выбранный ISP заменяется **одним** EcoRouter в той же ВМ.

**Если ISP уже заменены на EcoRouter, переходите сразу к шагу 5 — увеличению
памяти. Для изменения памяти повторять миграцию ОС не требуется.**

### Шаг 1. Открыть Shell нужной ноды Proxmox

В интерфейсе Proxmox выберите ноду → **Shell**. Выполняйте команды от `root`
на ноде, где находятся целевые ВМ. Посмотрите список ВМ и память хоста:

```bash
qm list
free -h
```

После увеличения памяти 16 ISP потребуют суммарно **80 ГиБ** вместо 64 ГиБ.
Дополнительно требуется 16 ГиБ, а также память для Proxmox и остальных ВМ.
Для миграции нужно свободное место под новые диски: старые диски сохраняются.

### Шаг 2. Скачать скрипт замены ISP

`curl -fL` скачивает файл с GitHub. Ссылка закреплена за конкретной версией
скрипта, использованной в этой инструкции.

```bash
curl -fL 'https://raw.githubusercontent.com/urijzubkov78-crypto/proxmox-isp-ecorouter/701e5ca992130e31b98c48f5e9e757e14e97df90/migrate_isp.py' -o /root/migrate_isp_ecorouter.py
```

Python 3.9+ и curl должны быть доступны на ноде. Установка через pip не нужна.

### Шаг 3. Проверить план замены

```bash
python3 /root/migrate_isp_ecorouter.py --vmids "$(seq -s, 10101 100 11601)"
```

Без `--apply` скрипт показывает план. Проверьте VMID, имена ISP, мосты и
хранилище. Остановка ВМ и импорт диска на этом шаге не выполняются.

Выбрать один ISP или другой набор можно так:

```bash
python3 /root/migrate_isp_ecorouter.py --vmids 10101
python3 /root/migrate_isp_ecorouter.py --vmids 10101,10301,10501
```

Допускаются только ВМ с именем `ISP` либо окончанием `-ISP` или `_ISP`.
Если имя или топология не подходят, разберите причину отказа перед применением.

### Шаг 4. Заменить выбранные ISP на EcoRouter

Этот шаг штатно выключит выбранные ISP и прервёт связь через них.
Скрипт добавит новый загрузочный диск EcoRouter, сохранив старые диски и
`protection`. После замены ВМ останутся выключенными.

```bash
python3 /root/migrate_isp_ecorouter.py --vmids "$(seq -s, 10101 100 11601)" --apply
```

Когда появится `Type exactly MIGRATE ... to continue:`, вставьте **всю**
следующую строку и нажмите Enter:

```text
MIGRATE 10101,10201,10301,10401,10501,10601,10701,10801,10901,11001,11101,11201,11301,11401,11501,11601
```

При другом наборе VMID используйте строку, которую покажет сам скрипт.
Затем он скачает образ EcoRouter (около 1,28 ГБ), проверит его и выполнит замену.
Дождитесь завершения. При ошибке ранее обработанные ISP могут уже быть заменены:
порядок повторного запуска описан ниже.

### Шаг 5. Увеличить память ISP с 4 до 5 ГиБ

Это отдельный скрипт: он меняет только память, не запускает миграцию ОС.
Его фиксированные цели — те же 16 ISP: `10101, 10201, …, 11601`.

Скачать скрипт и посмотреть план:

```bash
curl -fL 'https://raw.githubusercontent.com/urijzubkov78-crypto/proxmox-isp-ecorouter/701e5ca992130e31b98c48f5e9e757e14e97df90/resize_isp_memory.py' -o /root/resize_isp_memory.py &&
python3 /root/resize_isp_memory.py
```

Применить увеличение до **5120 МиБ (5 ГиБ)**:

```bash
python3 /root/resize_isp_memory.py --apply
```

Дополнительного ввода `MIGRATE` здесь нет: применение задаётся флагом `--apply`.
Скрипт проверяет все 16 целей до первой записи. Диски, сети, CPU и
`protection` сохраняются. ВМ автоматически не выключаются и не запускаются.

Если все ВМ находятся на одной ноде, но одна из целей отсутствует, имя не
соответствует ISP, есть блокировка, ballooning или посторонние отложенные
изменения, скрипт остановится с объяснением. Уже выставленные или отложенные
5120 МиБ при повторном запуске пропускаются.

Подробности: [MEMORY_5G.md](MEMORY_5G.md).

### Шаг 6. Запустить ВМ или применить отложенную память

**После миграции ВМ выключены.** Если готовы запускать все 16 ISP:

```bash
for vmid in $(seq 10101 100 11601); do
  qm start "$vmid" || break
done
```

При запуске они получат уже выставленные 5 ГиБ.

**Если память менялась у уже работающей ВМ**, Proxmox может отложить изменение.
В таком случае выполните полное штатное выключение и последующий запуск
через Proxmox. Пример для одного ISP, во время его выключения связь прервётся:

```bash
qm shutdown 10101 --timeout 180 && qm start 10101
```

Замените `10101` на нужный VMID. Если штатное выключение не завершится успешно,
вторая команда не выполнится. Перезагрузка только внутри гостя может не
применить новую память.

### Шаг 7. Проверить результат

Пример для одного ISP:

```bash
qm status 10101
qm config 10101 --current 1
qm pending 10101
```

В текущей конфигурации после применения должно быть `memory: 5120`.
Если 5120 МиБ пока только в отложенных изменениях, выполните выключение и запуск
из шага 6. Затем проверьте загрузку EcoRouter через Console в Proxmox.

WAN подключён к прежнему внешнему мосту, линк включён. DHCP, IP-адреса,
маршруты и NAT внутри EcoRouter скрипты не настраивают. Готовая связность
со старой сетью автоматически не восстанавливается.

## Справка по параметрам миграции

```bash
python3 /root/migrate_isp_ecorouter.py --help
```

Без `--vmids` скрипт покажет найденные ISP и предложит ввести нужные VMID
вручную. Автоматического выбора всех ВМ нет.

## Что происходит при замене

- Скрипт проверяет имя ISP, локальность, отсутствие блокировок, HA,
  репликации и неподдерживаемых настроек, доступность хранилища и образа.
- Исходная конфигурация, включая разделы снимков, сохраняется локально.
- Работающий ISP выключается штатно. Принудительного выключения нет.
- EcoRouter импортируется отдельным диском в свободный IDE-слот.
  Старые диски остаются подключёнными и не форматируются.
- Меняются загрузка, параметры оборудования и четыре сетевых адаптера ISP.
  `protection=1` не снимается. ВМ не удаляется.
- ISP остаётся выключенным. Скрипт не выполняет настройку внутри
  EcoRouter и не запускает гостевые команды.

В процессе замены связь через ISP прервётся. Старые настройки Linux не
переводятся в команды EcoRouter, и готовая маршрутизация автоматически
не появляется. При необходимости ISP можно запустить вручную из интерфейса
Proxmox либо командой `qm start VMID`. DHCP, IP-адреса, маршруты и NAT
пакет не изменяет и не создаёт.

## Сетевые адаптеры

| Адаптер | Назначение |
|---|---|
| `net0` | Служебный mgmt, `link_down=1` |
| `net1` | WAN, на исходном внешнем мосту, линк включён |
| `net2` | HQ, на исходном мосту ISP–HQ |
| `net3` | BR, на исходном мосту ISP–BR |

Все четыре используют `vmxnet3` и разные MAC с префиксом
`1C:87:76:40`. VLAN, firewall, MTU и другие параметры исходных рабочих
адаптеров сохраняются; на WAN линк включён. Это параметры подключения
виртуальной машины, а не настройка DHCP-клиента или IP-адреса внутри гостя. Поддерживаются две исходные схемы:
`net0/1/2 = WAN/HQ/BR` и `net0 = отключённый mgmt`, `net1/2/3 = WAN/HQ/BR`.
При иной схеме скрипт останавливается; явное сопоставление задаётся
параметрами `--wan-net`, `--hq-net`, `--br-net`.

Для нового ISP: 2 ядра и 4096 МиБ ОЗУ. При замене ISP с 512 МиБ расход
на один стенд увеличится на 3584 МиБ. На диске требуется место для нового
образа дополнительно к сохраняемым старым дискам.

## Повторный запуск и возврат

Состояние и исходные конфигурации хранятся в
`/root/proxmox-isp-ecorouter` (другой каталог: `--work`). Сохраняйте этот
каталог приватно: в нём находится конфигурация ваших ВМ.

При сбое повторно запускайте ту же команду с тем же `--work`.
Скрипт сверит состояние. Если результат импорта нельзя однозначно
восстановить, он остановится для ручной проверки, не создавая второй диск.

Возврат исходной загрузки, оборудования и сетей (VMID замените своим):

```bash
python3 /root/migrate_isp_ecorouter.py --vmids 10101 --rollback
```

Если после миграции уже увеличили память или иначе изменили оборудование,
автоматический возврат может остановиться из-за отличия от сохранённой конфигурации.
Сначала разберите сообщение об изменениях; не редактируйте сохранённое состояние
для обхода проверки.

Новый диск EcoRouter при возврате остаётся подключённым. Его удаление и
освобождение места не автоматизируются. Старые снимки, в том числе `Start`,
не переписываются: возврат к такому снимку может восстановить прежний ISP
на Linux. Сохранённая конфигурация не является резервной копией содержимого
всех дисков; старые диски сохраняются в исходной ВМ.

## Образ и требования

Proxmox с Python 3.9+, `qm`, `pvesh`, `qemu-img` и `kvm`.
Используются только стандартные библиотеки Python. `pip` и установка
дополнительных пакетов не нужны. Доступ к интернету нужен для скачивания
образа; локальный образ можно передать через `--image`.

Базовый образ взят из шаблона EcoRouterOS прежней конфигурации PavelAF:
[EcoRouter.qcow2 на Яндекс.Диске](https://disk.yandex.ru/d/WHdIBzZls5HZtQ/EcoRouter.qcow2).
Образ не включён в репозиторий или архив. Размер скачиваемого файла при
подготовке пакета: 1 276 903 424 байта. Зафиксированная SHA-256:

```text
3acf519eb775603cf53475dafb1db800ee18aca1ecd4ddd09589f92fe9aba481
```

Публичные ссылки разрешаются через API Яндекс.Диска. Временная ссылка
скачивания не выводится. Для стандартного образа перед импортом проверяются
зафиксированная SHA-256 и образ QEMU. Для своего локального образа ожидаемую
контрольную сумму можно указать через `--sha256`; для своего URL она обязательна.

## Проверка кода

```bash
python3 -m unittest discover -s tests -v
```

Для запуска всех тестов нужен полный каталог репозитория с папкой `tests`;
скачивание двух скриптов через curl не включает тесты.
Тесты моделируют команды Proxmox и не требуют действующей ноды. Проверка
на реальной ноде в ходе подготовки пакета не выполнялась. Перед массовой
заменой проверьте один ISP. Настройки гостевой сети в пакет не входят.

Репозиторий: [proxmox-isp-ecorouter](https://github.com/urijzubkov78-crypto/proxmox-isp-ecorouter).
