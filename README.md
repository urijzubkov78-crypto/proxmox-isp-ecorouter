# ISP на EcoRouter в существующих ВМ Proxmox

Сценарий заменяет загрузочную ОС выбранных ISP на EcoRouter, сохраняя VMID,
старые диски и флаг `protection`. HQ-RTR, BR-RTR и остальные ВМ не меняются.
Гостевые DHCP, IP-адреса, маршруты и NAT не настраиваются. Подключение WAN
сохраняет возможность дальнейшей ручной настройки внутри EcoRouter; поддержку
DHCP-клиента конкретной версии образа этот пакет не подтверждает.
Это отдельный инструмент для существующих стендов; установщик PavelAF для
нового развёртывания в этот пакет не входит.

## Запуск на Proxmox от root

Скопируйте и распакуйте пакет на ту ноду, где находятся нужные ISP.
Затем из каталога с `migrate_isp.py`:

```bash
python3 migrate_isp.py
```

Это просмотр плана. Скрипт покажет обнаруженные ISP и запросит их VMID.
Автоматического выбора всех ВМ нет. Для замены:

```bash
python3 migrate_isp.py --apply
```

Перед записью потребуется подтвердить точный список VMID. Пока вы не
подтвердили применение, остановка ВМ и импорт диска не выполняются.
Явные параметры для одного ISP (номер в примере замените своим):

```bash
python3 migrate_isp.py --vmids 10101 --apply
```

Список параметров:

```bash
python3 migrate_isp.py --help
```

## Что происходит при замене

- Скрипт проверяет имя ISP, локальность, отсутствие блокировок, HA,
  репликации и неподдерживаемых настроек, доступность хранилища и образа.
- Исходная конфигурация, включая разделы снимков, сохраняется локально.
- Работающий ISP выключается штатно. Принудительного выключения нет.
- EcoRouter импортируется отдельным диском в свободный IDE-слот.
  Старые диски остаются подключёнными и не форматируются.
- Меняются загрузка, параметры оборудования и четыре сетевых адаптера ISP.
  `protection=1` не снимается. ВМ не удаляется.
- ISP остаётся выключенным. Скрипт не выполняет настройку внутри
  EcoRouter и не запускает гостевые команды.

В процессе замены связь через ISP прервётся. Старые настройки Linux не
переводятся в команды EcoRouter, и готовая маршрутизация автоматически
не появляется. При необходимости ISP можно запустить вручную из интерфейса
Proxmox либо командой `qm start VMID`. DHCP, IP-адреса, маршруты и NAT
пакет не изменяет и не создаёт.

## Сетевые адаптеры

| Адаптер | Назначение |
|---|---|
| `net0` | Служебный mgmt, `link_down=1` |
| `net1` | WAN, на исходном внешнем мосту, линк включён |
| `net2` | HQ, на исходном мосту ISP–HQ |
| `net3` | BR, на исходном мосту ISP–BR |

Все четыре используют `vmxnet3` и разные MAC с префиксом
`1C:87:76:40`. VLAN, firewall, MTU и другие параметры исходных рабочих
адаптеров сохраняются; на WAN линк включён. Это параметры подключения
виртуальной машины, а не настройка DHCP-клиента или IP-адреса внутри гостя. Поддерживаются две исходные схемы:
`net0/1/2 = WAN/HQ/BR` и `net0 = отключённый mgmt`, `net1/2/3 = WAN/HQ/BR`.
При иной схеме скрипт останавливается; явное сопоставление задаётся
параметрами `--wan-net`, `--hq-net`, `--br-net`.

Для нового ISP: 2 ядра и 4096 МиБ ОЗУ. При замене ISP с 512 МиБ расход
на один стенд увеличится на 3584 МиБ. На диске требуется место для нового
образа дополнительно к сохраняемым старым дискам.

## Повторный запуск и возврат

Состояние и исходные конфигурации хранятся в
`/root/proxmox-isp-ecorouter` (другой каталог: `--work`). Сохраняйте этот
каталог приватно: в нём находится конфигурация ваших ВМ.

При сбое повторно запускайте ту же команду с тем же `--work`.
Скрипт сверит состояние. Если результат импорта нельзя однозначно
восстановить, он остановится для ручной проверки, не создавая второй диск.

Возврат исходной загрузки, оборудования и сетей (VMID замените своим):

```bash
python3 migrate_isp.py --vmids 10101 --rollback
```

Новый диск EcoRouter при возврате остаётся подключённым. Его удаление и
освобождение места не автоматизируются. Старые снимки, в том числе `Start`,
не переписываются: возврат к такому снимку может восстановить прежний ISP
на Linux. Сохранённая конфигурация не является резервной копией содержимого
всех дисков; старые диски сохраняются в исходной ВМ.

## Образ и требования

Proxmox с Python 3.9+, `qm`, `pvesh`, `qemu-img` и `kvm`.
Используются только стандартные библиотеки Python. `pip` и установка
дополнительных пакетов не нужны. Доступ к интернету нужен для скачивания
образа; локальный образ можно передать через `--image`.

Базовый образ взят из шаблона EcoRouterOS прежней конфигурации PavelAF:
[EcoRouter.qcow2 на Яндекс.Диске](https://disk.yandex.ru/d/WHdIBzZls5HZtQ/EcoRouter.qcow2).
Образ не включён в репозиторий или архив. Размер скачиваемого файла при
подготовке пакета: 1 276 903 424 байта. Зафиксированная SHA-256:

```text
3acf519eb775603cf53475dafb1db800ee18aca1ecd4ddd09589f92fe9aba481
```

Публичные ссылки разрешаются через API Яндекс.Диска. Временная ссылка
скачивания не выводится. Для стандартного образа перед импортом проверяются
зафиксированная SHA-256 и образ QEMU. Для своего локального образа ожидаемую
контрольную сумму можно указать через `--sha256`; для своего URL она обязательна.

## Проверка кода

```bash
python3 -m unittest discover -s tests -v
```

Тесты моделируют команды Proxmox и не требуют действующей ноды. Проверка
на реальной ноде в ходе подготовки пакета не выполнялась. Перед массовой
заменой проверьте один ISP. Настройки гостевой сети в пакет не входят.
